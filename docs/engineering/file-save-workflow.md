# 真实文件保存与冲突

默认运行目标 `xdnote` 提供独立窗口的单文件功能闭环。`xdnote-admission` 仍只操作内存样本。打开范围、字节准入和身份方案见[文件读取](file-read-baseline.md)，用户交互以[交互规格](../product/interaction-spec.md)为准。

## 会话与异步操作

`FileApplication` 把命令行、系统文件打开事件、应用内选择及拖入交给同一个 `FileManager`。用户级 `SingleInstance` 使用访问受限的本地 socket、启动锁、定长上限的 JSON 帧和接收确认；后续进程只转交路径，失败明确退出。同一身份经 `SessionRegistry` 复用已有会话与窗口，不重新读盘覆盖未保存内容。安装器的文件关联注册尚未实现。

后台文件操作按完成回执串行执行，编辑仍在 GUI 线程进行。`DocumentSession` 持有唯一原文和撤销，保存捕获不可变的 `DocumentId`、revision、UTF-8 正文及独立 BOM 标记。回执核对请求 ID 和文档 ID，只有确认写入的快照更新保存基线。保存期间的新编辑保留为 dirty，旧回执不能把新内容标为已保存。替换和另存为改变文件身份时先重绑定登记，不建立第二个编辑缓冲区。

重新载入记录请求前版本；读取期间又有编辑或输入法组合时拒绝应用结果，保留当前编辑。成功载入为可撤销的会话命令，更新磁盘基线。另存为拒绝覆盖另一个已打开会话的文件；普通保存遇到文件删除不自动重建，用户明确另存为到该路径才允许重新创建。

## 保存阶段和结果

`FileService::save` 依次执行 `Validate`、`StageWrite`、`Commit`、`Verify`，返回阶段、类型化错误和原生错误码。普通保存不截断原文件，也不回退到直接原位写入。

| 结果 | 含义与界面行为 |
| --- | --- |
| `Committed` | 已观察到目标身份与冻结字节一致、被替换版本仍符合基线，清理成功；确认该快照，更新保存状态 |
| `Conflict` | 目标身份／字节变化，或新建目标已经出现；保留编辑，提供保留、重新载入、另存为 |
| `Failed` | 提交前失败，或平台失败后可确认原文件未改变；保留编辑和 dirty，显示可重试原因 |
| `Uncertain` | 已提交后校验失败、替换过程存在部分结果，或恢复材料无法安全清理；不确认保存，显示磁盘恢复副本及暂存位置，不自动回滚 |

写入同目录唯一暂存文件，完整写入并 flush 后释放实际原生句柄；仅调用 `QTemporaryFile::close()` 不足以释放 Windows 句柄。提交前再次比对文件身份和完整字节。新建采用不覆盖已有目标的提交方式。正常成功清理临时文件；异常结果的恢复副本有明确用途和位置，不作为历史版本存储，也不自动删除其他程序的数据。

Windows 使用 `ReplaceFileW` 并保留被替换对象至校验完成，不设置忽略 ACL 合并错误的标志；提交期间排除普通数据写入句柄，父目录句柄限制常规重命名。Linux 使用 `renameat2(RENAME_EXCHANGE)`，macOS 使用 `renameatx_np(RENAME_SWAP)`，通过已打开父目录交换目标与暂存路径。文件系统不支持交换时明确失败，不降级为未经保护的普通覆盖。POSIX 保留权限及扩展元数据，复制失败或带特殊权限／能力的目标明确拒绝。

交换后核对被替换对象的身份与完整字节，再核对目标身份和保存正文；在检查后竞争替换的受控测试中，返回 `Uncertain` 并保留被移出的版本。不会盲目把磁盘路径回滚而覆盖后续外部修改。所有这些是已观察到的结果，不是跨进程内容比较交换：POSIX 其他进程持有的可写 FD 仍可在最后观察后修改旧对象，任意命名空间竞争也不能由多次观察完全排除。这里不承诺恶意并发程序、特殊卷、网络卷或断电情况下的全面原子性与持久性。

## 编码与文件保护

首轮接收不超过 2 MiB 的严格 UTF-8 正文，编码 BOM 可选且独立记录。无效 UTF-8、NUL、超额及非普通文件明确拒绝；不猜测或替换编码，不规范化混合换行。原文首字符 U+FEFF 作为正文保存，必要时增加独立编码 BOM，确保重新读取不会吞掉正文字符。只读文件仍可阅读并另存为；保存失败不清除编辑内容。

多硬链接文件已确定采用另存为保护：原子替换会使其他硬链接继续指向旧对象，因此不在原路径保存，提示选择另一目标。读取时各别名继续共用会话。符号链接、Windows 最终重解析点及当前未准入的路径类型按读取规则拒绝。首次支持范围不扩展为任意文件系统保证。

## 冲突、关闭与验证

每两秒及窗口激活时请求有界大小的后台基线核验。观察到外部修改、删除或无法读取时保留当前内容并显示提示；不自动覆盖磁盘，不自动丢弃 dirty。重新载入 dirty 内容须再次确认；选择保留继续编辑，选择另存为走同一安全保存流程。瞬时占用解除且磁盘仍等于基线时可恢复普通保存。

关闭 dirty 窗口提供保存、不保存、取消；取消与关闭确认框保持原编辑，保存失败保持窗口。操作未结束时可等待后关闭或取消关闭；回执期间新增编辑会重新提示。退出按窗口依次处理，任何取消停止退出，不绕过未保存确认。

自动化使用自建真实临时文件及实际 QWidget／Scintilla／WebEngine，覆盖 Unicode 路径、BOM、混合换行、硬链接保护、同文件多入口、保存期间编辑、另存为、占用／只读失败、提交前后竞争、重新载入、取消／放弃／保存后关闭和第二进程转交。测试输出和当前窗口截图只存放于忽略的构建目录或 CI 工件。构建入口见[开发构建](developer-build.md)；自动化不代替人工输入法、辅助技术、系统关联、最低系统、实际跨屏拖动及安装验收。
