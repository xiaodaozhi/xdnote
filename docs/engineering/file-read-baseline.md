# 文件读取与会话登记

`FileService` 和 `SessionRegistry` 是真实文件闭环的基础 API，目前通过自建临时文件自动验证。运行器仍只操作内存样本，尚未接入用户文件打开、保存、监测或产品界面；本页不表示单文件闭环已完成。整体契约见[技术架构](architecture.md)和[打开与关闭交互](../product/interaction-spec.md)。

## 调用顺序与所有权

1. 在后台调用 `FileService::probe`，取得实际打开对象的身份及持有该对象的只读元数据句柄。此时不读取或解码正文。
2. 界面线程调用唯一应用级 `SessionRegistry::beginOpen`。已有会话返回 `Reused`，直接激活其承载者；关闭中的会话返回 `Closing`。新对象返回带唯一请求 ID 的 `Pending` 和 `startRead=true`；同一对象正在读取时复用请求 ID，`startRead=false`，调用方加入已有请求。
3. 只有新请求在后台执行 `FileService::read`，结果包含同一请求 ID、文件身份、原始字节、UTF-8 正文、BOM 标记及 SHA-256 摘要。它不读取活动编辑器，也不改写磁盘。
4. 界面线程通过 `SessionRegistry::complete` 核对请求 ID、文件身份与当前登记。首次完成创建唯一 `DocumentSession`；同一请求的重复完成复用已有原文和撤销，不把旧读取内容写回缓冲区。
5. 读取失败或打开意图取消时，调用方展示类型化错误并调用 `cancel` 撤销尚未完成的登记。取消、会话关闭及重新请求使旧 ID 失效；迟到结果返回 `StaleRequest`。`cancel` 不关闭已经建立的会话，也不强制中断运行中的系统调用。

注册表持有会话和读取基线，调用方只持有会话弱引用。会话带稳定 `DocumentId`，快照携带相同 ID 与文本版本；当前 dirty 读取 Scintilla 的内容／撤销保存点，撤销回到初始载入内容可以恢复 clean。保存期间的快照基线更新尚未实现，不能用这个初始保存点宣称已写盘。

关闭信号之后，注册表通过排队回调解除登记并延后释放会话；关闭期间不能接入新读取结果。清理回调同时核对请求 ID，旧会话延后销毁不能清除已经登记的新请求。这里不提供保存、放弃或取消提示，应用协调层仍须先按产品关闭契约完成确认。完整打开路由、失败页面、IPC、窗口迁移和应用退出继续独立实现。

## 身份与路径范围

Windows 使用 `FileIdInfo` 的卷序列号与 128 位文件 ID，Linux／macOS 使用设备号与 inode。身份句柄在登记或基线存活期间保持打开，避免原对象释放后身份复用；硬链接及不同路径拼写指向同一对象时共用会话，同路径被替换为另一对象时取得新身份。句柄使用允许其他程序读、写及替换的共享方式，不把应用内去重当作跨进程锁。

入口接收明确选择的、有效 Unicode 绝对路径，只接受普通文件。最终符号链接、重解析点、目录和其他非普通对象均拒绝；Windows 当前另拒绝 UNC、设备／命名管道命名空间及备用数据流，不承诺长路径或特殊卷支持。Linux／macOS 的最终链接用原生不跟随标志处理，元数据探测不会等待 FIFO 的读写对端。

父路径由系统正常解析，入口不把路径词法折叠或大小写猜测当成文件身份。这只适用于调用方已经明确选择的单文件；它不是工作区或预览资源的授权 API，不能据此放行中间链接、重解析点或根目录越界。工作区资源仍按[资源契约](../product/workspace-resources.md)另行核验。

## 字节与失败语义

当前读取入口只接受严格 UTF-8，可带一个编码 BOM。编码 BOM 独立记录，正文中的 U+FEFF 不再被默认解码吞掉；会话、UTF-16 位置转换及辅助功能使用同一原文解码规则。混合 CRLF／LF／CR、中文、补充字符和 Unicode 分隔符保持原字节，不规范化换行。无效或截断 UTF-8 不猜测编码、不替换后继续载入；含空字符的文件在当前读取入口明确拒绝，内存会话对空字符的保留能力与该文件准入政策分别记录。

源文额度为当前组件准入的 2 MiB，编码 BOM 另计三字节，不是正式产品容量承诺。读取受字节额度限制，并比较实际打开对象、读取前后元数据、两次完整读取结果及完成时的路径身份；观察到变化时返回 `Changed`。缺失、权限不足、Windows 占用、非普通对象、无效编码、超过额度和其他 I/O 失败分别返回错误类别、原生错误码及中文说明，不生成部分成功基线。

上述核验不是跨进程原子读取，也不能排除其他程序在观察点之间修改再恢复内容，或在最终核验后继续修改。读取基线只是已观察到的不可变输入，不能直接充当跨进程比较交换令牌。工作线程同步执行系统调用，不保证任意文件系统上的墙钟时限；网络卷、特殊卷、完整路径授权及更强的取消与隔离仍须准入。

## 验证边界

桌面测试使用自身创建的真实临时文件，覆盖字节／BOM、初始 U+FEFF 与编辑位置、混合换行、硬链接别名、dirty 会话复用及撤销、同路径替换、无效内容、额度、占用／权限、取消／关闭后的迟到回执和线程归属。Windows 用受控目录联接验证重解析点拒绝；POSIX 验证最终符号链接和 FIFO；不能将这些结果扩大为全部文件重解析标签、卷类型或原生产品集成已通过。

正式写盘、外部变化监测、保存中的编辑、提交前失败／已提交／结果不确定分类、无损保存往返和关闭提示仍未完成。自建文件测试和 CI 不替代用户目录、真实输入法、辅助技术、文件管理器或最低系统验收，实际构建方法见[开发构建](developer-build.md)。
