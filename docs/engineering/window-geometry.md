# 跨显示器缩放与窗口几何

**状态：独立文件窗口已接入共享几何实现，跨屏平台验收待完成。** 本页约束 xdnote 自有顶层窗口的尺寸、跨屏迁移和几何恢复。当前实现入口为 `apps/desktop/src/WindowGeometry.cpp`；工作区、完整设置和其他尚未实现的窗口不视为已经接入。应用范围见[窗口登记](../visual/window-registry.json)，建议几何与组件值仍以[视觉参数](../visual/tokens.json)为准。实际提交、自动化及真实设备结果记录在 Issue 中。

## 尺寸目标与单位

普通窗口在高缩放与低缩放显示器之间移动时，保持用户设定的**逻辑客户区尺寸**。目标可用区域不足时仅做必要的收敛，不因旧屏幕倍率、重复换算或最小尺寸错误而扩大；反复往返不得累计增长。高分辨率不等于高缩放，不能只凭显示器的像素分辨率决定窗口尺寸。

| 数据 | 单位与责任 |
| --- | --- |
| 客户区、组件、字体、最小／最大设计尺寸 | Qt 逻辑像素；共享参数和布局不再乘系统缩放或 DPR |
| 渲染表面与栅格素材 | 窗口当前有效 DPR 对应的设备采样；不能假定等于应用全局或显示器 DPR |
| Windows 原生外框、客户区、边框和跟踪约束 | Win32 边界的设备像素；仅在平台层按本次有效 DPI 换算 |
| 可用区域与窗口位置 | 同一平台、同一坐标空间内比较；屏幕原点不能跟随尺寸倍率一起相乘 |
| 持久化的正常尺寸 | 逻辑客户区及明确的版本／状态；截图、物理外框和上次倍率不是尺寸真值 |

在原生客户区直接对应设备像素的 Windows 标准缩放路径下，关系为 `设备客户区 ≈ 逻辑客户区 × DPI / 96`，外框还要加上窗口样式和目标 DPI 的非客户区度量。以下仅为算术示例，不替代窗口参数：

| 普通窗口位置 | 逻辑客户区 | 预期设备客户区 |
| --- | --- | --- |
| 150% 显示器 | 1000 × 700 | 1500 × 1050 |
| 移至 100% 显示器 | 1000 × 700 | 1000 × 700 |
| 返回 150% 显示器 | 1000 × 700 | 1500 × 1050 |

设备像素变化是正常的；把 1500 × 1050 重新当作目标屏上的逻辑尺寸则是缺陷。macOS 和 Linux 可能还有合成器缩放，不能将 Win32 换算或截图物理像素套入其窗口几何。Qt 坐标边界见 [High DPI](https://doc.qt.io/qt-6.8/highdpi.html)；已知目标窗口时优先使用 [QWindow 的有效 DPR](https://doc.qt.io/qt-6.8/qwindow.html#devicePixelRatio)。

## 唯一几何所有者

桌面层统一协调工作区、独立文件、设置、比较及应用自有弹窗的几何；按实际窗口逐一接入，不预建空容器。`WindowGeometry` 在界面线程协调当前独立窗口，分别管理正常逻辑客户区与还原位置、当前实际几何与有效缩放、系统窗口状态、临时可用区收敛及更新代次。`rememberUserGeometry` 仅接收明确的用户或应用尺寸意图；DPI 与可用区回调不得调用它来覆盖偏好基线。

QML／控件声明共享布局、逻辑约束和用户意图，平台层负责原生边界，不能分别持有可相互覆盖的尺寸真值。`screenChanged`、DPR、resize、主题和延迟回调可能交错，更新须幂等并拒绝过期回执，不在每次通知中重新乘倍率或通过反复 `setGeometry` 形成反馈循环。

用户实际拖动边缘调整尺寸时更新偏好基线；纯移动、DPI 迁移、最大化或临时适配不覆盖基线。移动和调整大小同时发生时保留本次原生请求的调整量，不只恢复迁移开始时的旧快照。字体偏好变化是独立意图，按共享布局重排，不借 DPI 回调静默重置字体或密度。

## 跨屏与目标可用区

1. 拖动优先进入平台系统移动／缩放流程，保留光标锚点、吸附和动画；不逐帧拉回主屏、反复居中或重建承载。
2. 区分当前窗口 DPI、待切换 DPI、窗口状态和目标可用区。Qt 信息未完成更新时，不拿旧屏幕倍率核算新屏原生约束。
3. 普通窗口容纳得下时保持逻辑客户区。稳定落位后若容纳不下，按可用客户区收敛并约束位置，保留必要操作可达；迁移中跨越边界不触发反复回拉。
4. 可用区域扣除系统保留区及实际装饰，不能只拿像素分辨率或整个虚拟桌面包围矩形作为可用区。支持负坐标，逐屏核对；虚拟桌面空隙不是显示区域。
5. 目标小于常规设计最小值时，使用共享紧凑布局、可选侧栏收起、正文滚动或菜单溢出，保留标题栏、关闭、保存和确认入口，不缩小文字抵消系统缩放。有效原生最小约束与该布局一致，不能继续用超过可用区的旧最小值撑大窗口；尚无可用布局时记录限制并讨论，不伪造全尺寸可用结论。
6. 临时收敛与用户偏好分开保存。返回足够大的区域时可恢复迁移前的正常尺寸，最多恢复到未被用户改动的偏好基线；用户在小屏主动调整后以新意图为准，不强行回弹。

菜单、提示和应用自有子窗口按实际目标屏的有效缩放与可用区域定位，不能盲用父窗口此前的倍率；系统文件选择器等平台自有界面交由系统处理。

## Windows 原生适配

正式 Windows 窗口验证 Per-Monitor V2 配置，默认沿用 Qt 与系统的正常协商。只有存在可复现偏差且相关 Qt 版本、样式与配置验证后，才接管必要消息；不全局禁用高 DPI、强制固定倍率或依赖 Qt 私有客户区修正掩盖问题。

### 过渡期尺寸与跟踪约束

`WM_GETDPISCALEDSIZE` 的目标 DPI 与可读写 `SIZE` 对应本次待切换尺寸，输入可能包含用户缩放请求。需要定制外框时，在匹配的原生坐标中保留客户区及待处理尺寸增量，再按当前到目标 DPI 换算客户区，最后加上目标 DPI、实际样式与菜单状态的非客户区度量。不能简单缩放旧外框或忽略调整量。消息语义见 [WM_GETDPISCALEDSIZE](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-getdpiscaledsize)。

`WM_DPICHANGED` 期间 HWND 可能已采用新 DPI，Qt 却暂时引用旧屏幕。此时处理 `WM_GETMINMAXINFO`，原生最小／最大跟踪尺寸以 [GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow) 的当前 DPI 和相同边框度量计算；未来待切换尺寸仍用对应消息的目标 DPI，不能将两者混为缓存值。回归必须覆盖 HWND=96 DPI、Qt 暂报 1.5 倍的状态，才可验证旧最小约束导致的撑大路径。

确需接管时，用 [AdjustWindowRectExForDpi](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-adjustwindowrectexfordpi) 等与样式匹配的度量。仅修改已验证需要接管的跟踪字段，保留系统最大化位置、最大化尺寸及其他未处理字段；无限制轴保留系统限制，不将框架哨兵当作真实尺寸。参考 [WM_GETMINMAXINFO](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-getminmaxinfo) 与 [WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)。

### 接管范围与失败处理

定制处理只作用于本进程、正确线程、有效且归属匹配的原生窗口。状态、样式、感知模式、舍入策略和缩放覆盖纳入准入；最大化、最小化、全屏及不同装饰不自动复用普通窗口算法。不支持的组合保留系统／Qt 处理，不能先改写半份消息再回退。

Qt 6 默认 PassThrough 作为基准验证。`QT_SCALE_FACTOR`、`QT_SCREEN_SCALE_FACTORS`、旧 DPI 覆盖和不同舍入策略属于独立配置，记录并验证实际映射，不能假设窗口 DPR 恒等于 HWND DPI 除以 96。自定义路径不满足前提时交回框架，不修改用户环境；基准通过不表示所有覆盖配置通过。

原生计算校验句柄、线程、DPI、正尺寸、边框和溢出，完整成功后一次提交；失败不修改借用参数。消息指针仅在同步回调中使用，不存入延迟任务。不把某种标题栏的固定设备边距套到所有窗口。

### 初始化与重复事件

确需首次绑定时补偿客户区的窗口，按原生句柄寿命只执行一次。主题、DPI、合成变化和重复绑定仅刷新装饰，不再次添加边框、恢复初始宽高或扩大客户区；句柄销毁重建后重新核验归属及初始化状态。重入保护和失败路径不能把半完成绑定标为成功。

`WM_DPICHANGED` 的建议矩形、Qt 后续处理和应用适配须有唯一完整责任链：未接管时继续默认处理，部分接管时明确保留路径，不能截断 DPI 更新或让两层重复补偿。纯装饰刷新不递归触发尺寸协商。

## 平台状态与几何恢复

Windows 自绘标题栏的按钮和双击通过系统最大化／还原命令切换，保留系统动画设置，不模拟逐帧缩放或修改用户的动画偏好。Qt Widgets 的客户区声明与 HWND 的系统样式分别管理；原生状态命令发出前及同步窗口回调中通知几何协调器，过渡期 resize 不能更新正常尺寸偏好。适配屏幕前同时核对 HWND 的最大化／最小化状态和 Qt 状态，不能在 Qt 尚未同步时对仍处于系统特殊状态的窗口写入普通尺寸。正常尺寸、原生命令、程序化往返与实际鼠标／动画感受分别验证。

| 场景 | 行为 |
| --- | --- |
| 最大化、系统贴靠／平铺 | 服从目标屏及系统状态，不强行恢复普通尺寸；另存正常还原几何 |
| 全屏与最小化 | 特殊状态尺寸不覆盖正常偏好；还原时核验当前显示器，保留系统生命周期 |
| 屏幕断连、扩展坞、运行中更改缩放／分辨率 | 核验当前屏幕和缩放，恢复不可达窗口，避免重复补偿及偏好污染 |
| 新建应用弹窗 | 使用所属窗口当前屏幕／平台瞬态关系，遵循共享逻辑尺寸和可用区 |
| 恢复普通窗口 | 读取有版本逻辑尺寸与状态，核验有效屏幕及可见区域；原屏不存在时选择所属窗口屏或可用主屏等有效目标 |
| 无效配置或首次启动 | 回到窗口登记引用的共享参数，拒绝零／负尺寸及不合理越界值，不读取位图大小 |

保存正常尺寸时忽略初始化、迁移中间态、临时夹取和特殊状态通知，不把设备尺寸持久化为逻辑值。屏幕标识只帮助选择目标，不保证一直存在，也不在公开日志输出私人硬件标识。位置按明确坐标基准存储并在恢复时核验，不将原生几何盲目用于不同拓扑。

`WindowActive` 只表示激活，不是最大化、最小化或全屏；正常尺寸判断和原生 resize 必须忽略该位，仅激活变化不触发还原拟合。正常几何附带 `normalVersion=2`，旧记录未标记时按 1 读取。Windows 旧记录若同时声明最大化且普通尺寸等于已存可用区，按当前窗口的设计默认普通尺寸恢复一次；其余旧记录保留尺寸，新记录允许用户有意设置铺满可用区的普通窗口，不能每次启动重置。

macOS 按系统窗口和 backing scale 更新采样与布局，保持正常逻辑尺寸，不移植 Win32 消息或边框常量。X11 保留区和装饰信息存在窗口管理器差异，不把整屏范围宣称为已排除任务栏的精确结果。Wayland 通常不允许任意查询／设置顶层全局位置，使用系统移动／缩放及瞬态关系，由合成器安置，不循环设置坐标或承诺跨启动精确复位。依据见 [Qt 窗口位置说明](https://doc.qt.io/qt-6.8/qwindow.html#setPosition)、[窗口管理差异](https://doc.qt.io/qt-6.8/application-windows.html)及 [QScreen 可用区域限制](https://doc.qt.io/qt-6.8/qscreen.html#availableGeometry-prop)。

几何偏好存于用户级窗口状态，不写入文档／工作区，不保存正文或引入会话／崩溃恢复承诺。持久化失败不影响正文，按实际结果反馈，不虚报尺寸已记住。

首次显示即记录实际屏幕可用区；窗口已处于最大化或平台 zoom 状态时，跳过正常尺寸拟合也必须保留有效恢复上下文。应用明确调整正常尺寸时通过几何控制器登记意图，再进行可用区收敛，不由旁路 `resize` 与恢复偏好反复竞争。

当前 `WindowGeometryStore` 使用独立的 `settings.json.windows` 用户级文件，避免外观设置与几何设置互相覆盖。结构版本为 1，按窗口用途保存正常逻辑客户区矩形、上次可用区和最大化偏好；不记录显示器硬件标识或文件路径。关闭或最小化的瞬时尺寸不成为正常尺寸，临时收敛不会写回偏好宽高。损坏、过大和未知版本配置保留原文件并反馈；合法配置通过 `QSaveFile` 原子提交。无可用原屏时约束到当前有效屏，Wayland 不请求恢复全局位置。

当前独立窗口还没有低于设计最小尺寸的完整紧凑布局。若扣除系统外框后的可用区小于最小布局，保留布局约束与可达的顶部位置并明确反馈，不宣称全窗口已经容纳；进一步紧凑布局属于待验收部分。系统贴靠／平铺缺少统一 Qt 状态标记时，保留贴住可用区边缘的系统安排，不在其上强行恢复普通窗口尺寸。

## 验证与准入

窗口派生类析构时，应在界面成员仍有效期间保存并释放几何控制器、移除原生与 Qt 事件过滤器，断开会回写界面的外部信号。不能仅依赖 QObject 子对象的最终清理：QWidget 基类销毁原生窗口时仍可能投递 Hide，进而使控制器在派生类成员销毁后重新进入界面回调。工作区接管与应用退出共同遵守此生命周期边界；自动化覆盖直接销毁仍可见的独立窗口和工作区。

记录窗口用途、样式、系统／Qt／构建身份、窗口状态、Qt 窗口与屏幕 DPR、原生 DPI、逻辑及原生客户区／外框、跟踪约束和可用区域。预期值、取整及平台容差须事先明确且有依据，不能扩大容差、重试直到成功或反复重置窗口来掩盖增长。

| 层次 | 必须覆盖 | 证据边界 |
| --- | --- | --- |
| 确定性自动化 | 100%、125%、150%、200% 双向换算、奇数尺寸、Qt 旧倍率与 HWND 新 DPI、零／无限制、无效／溢出、未处理字段、其他窗口、重复事件、收敛与用户偏好分离 | 计算与处理边界，不代替系统 DPI 迁移 |
| 原生程序化迁移 | 真实不同缩放屏幕、自建窗口的实际 DPI 消息、Qt 更新前约束、延迟装饰刷新后的持续采样及往返；单独屏幕 setter 或合成消息不算 | 此环境原生协商，不等于鼠标验收 |
| 真实鼠标与视觉 | 150%→100%→150% 等物理往返、光标锚点、落位、正文／侧栏留白、标题栏与菜单、最大化还原、边缘调整、操作可达及重复迁移 | 桌面操作与视觉，按平台分别记录 |

覆盖同倍率不同分辨率、同分辨率不同倍率、目标空间不足、负坐标、拔插、运行中改缩放、跨启动恢复和应用字号 100%／125%／150%。比较稳定逻辑客户区及原生度量，外框装饰差异不直接判作客户区错误；返回原屏后回到预期正常基线，不累计漂移。

`QT_SCALE_FACTOR` 单屏、离屏 CI、截图缩放、程序化移动和物理拖动分别记账。缺少真实显示器时记录未执行／跳过及原因，对应准入保持未完成。Qt 或平台适配升级后重跑初始客户区、原生约束、往返和窗口状态回归，并单独补原生／人工验收。

实际实施由 [Issue #54](https://github.com/xiaodaozhi/xdnote/issues/54) 跟踪，映射见[验收规格](../qa/acceptance.md)。结论须关联实际提交与环境，本文不表示当前产品已通过。

## 可用区小于常规布局

几何控制器默认保留窗口登记的最小布局。只有实现了响应式布局的窗口才显式提供紧凑最小尺寸：设置窗口为 480×320，常规最小尺寸仍是 860×640。控制器按实际可用客户区临时放宽 QWidget 的最小约束，回到较大工作区时恢复常规约束；正常逻辑尺寸偏好不被临时收敛覆盖。未声明紧凑能力的窗口不自动继承这项放宽。低于紧凑最小布局的屏幕继续显式反馈限制。

设置侧栏和正文独立滚动，固定完成按钮保持可达；应用弹窗按当前工作区裁定可见尺寸，极小区域使用内容滚动保留完整动作。离屏小屏幕配置用于验证布局和动作可达，不代表原生 DPI 协商、鼠标跨屏或最低系统验收。
