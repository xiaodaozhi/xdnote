# 整应用资源测量

`tools/app-performance.json` 定义 Windows 开发构建的固定场景：空工作区、单文档阅读、单文档编辑、双栏和八标签工作区。原文含中文、Unicode、本地图片、代码、表格和任务列表，单文件保持在当前 2 MiB 准入上限内。`scripts/app_performance.py` 为每个场景启动独立的 `xdnote_app_probe` 进程，默认五次，保留输入摘要、原始样本、日志及中位数和最近秩 P95；不从旧的渲染工作进程预算推导整应用预算。

```text
python scripts/app_performance.py --build-dir <当前构建目录> --qt-prefix <本项目 Qt 6.8.2 目录> --output build/<专用证据目录>
```

探针复用产品的 GUI 初始化、字体与图标、唯一文件会话、设置、导航、恢复计时器、自动保存控制器、原生编辑／阅读控件和工作区，IPC 使用独立目录。`FileApplication::Presentation::HiddenNative` 仅供受控探针显式使用，在第一次显示前设置隐藏原生窗口属性；产品默认仍正常显示。配置与文档由测量入口创建，探针不读取用户偏好、不改变主题、不发送桌面输入、不截取桌面。Qt 自身绘制完成用于检查阅读布局，不能替代可见窗口的合成显示验收。

父进程测量从创建子进程到观察到原子写入的就绪文件，包含进程及 DLL 启动开销，就绪轮询间隔为 10 ms。子进程另外记录进入 `main` 后的 GUI 初始化、文件会话打开和初次 Qt 绘制时间。进入 `main` 前的动态加载不包含在这些子阶段内。文件样本在启动计时前生成；重复测量使用正常系统缓存，不宣称冷启动。

Windows 使用当前进程 `GetProcessMemoryInfo` 分别记录工作集、专用提交量和峰值工作集，初次就绪及约 2.4 秒空闲期间均保留样本。峰值工作集是自进程创建以来的峰值，不能当成某个瞬间的私有内存。八标签场景保留全部会话，等待活动页完成阅读布局，未激活页不强制创建可见布局。统计不汇总系统合成器和外部助手进程；本入口目前只支持 Windows，不将其他平台的数值记为零。

编辑场景通过会话 API 更新十二次并等待对应预览稳定，再验证撤销恢复原始字节、实际保存字节一致和阅读／编辑／双栏切换。记录的是命令到受控布局稳定时间，不能作为真实键盘、中文输入法或滚动帧率指标。失败、超时及严重 Qt 诊断会使测量失败，日志予以保留。

`--payload <精简安装载荷>` 使用该目录的 DLL／插件／QML 和 Windows 系统目录，诊断探针留在构建目录；入口校验实际加载的 Qt Core 路径。载荷内不需要 Qt Test 或离屏插件。此项证明当前主机上的独立运行依赖，不证明最低系统、安装交互或发行签名。

整应用资源预算须依据有效样本单独制定。输入法、屏幕阅读器、物理跨屏、冷缓存及可见桌面响应仍分别验收。具体运行结果记录在 Issue 和工件中，文档不保存单次性能成绩。
