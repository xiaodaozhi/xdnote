# 工作区图片与文档链接

**状态：实施规格，部分图片预览与导入已接入。** Windows 和 Linux 的受限本地图片预览、Windows 工作区图片导入及各平台当前限制见[资源基础](../engineering/workspace-resource-foundation.md)；其他平台和独立窗口图片导入、链接管理、引用索引和移动维护尚未完成。用户已确认工作区新增受管图片默认集中在 `assets/images/`，正文使用相对路径。需求见[产品需求](requirements.md)，统一会话、保存与关闭见[交互规格](interaction-spec.md)，职责见[技术架构](../engineering/architecture.md)。

## 普通文件与解析基准

工作区是用户显式打开的目录。Markdown 和图片始终是普通文件，可用其他编辑器及 Git 管理；不导入私有资料库，不要求把私有标识或应用 URI 写进正文。索引是可重建的派生数据，存于用户缓存位置；打开目录本身不创建资源目录、索引文件或项目配置，不新增工作区配置继承链。

所有新生成的图片和文档引用都以**当前 Markdown 文件所在目录**为相对基准，使用 `/` 分隔。`assets/images/` 是工作区内的存储目标，不是所有文档共用的 URL 基准。例如工作区包含 `README.md`、`notes/方案.md` 和 `assets/images/示意图.png` 时：

| 引用来源 | 图片目标 | 指向另一个文档的目标 |
| --- | --- | --- |
| `README.md` | `assets/images/示意图.png` | `notes/方案.md` |
| `notes/方案.md` | `../assets/images/示意图.png` | `../README.md` |

上表展示未做 URL 编码的逻辑路径。应用生成正文目标时逐路径分量处理 URL 编码：空格、`#`、`?`、`%` 和中文必须正确往返，不把文件名中的井号当作标题片段；已有合法中文目标继续兼容。解析时先按 Markdown 语法取得目标，再拆分路径与片段、仅解码一次、核验路径；不把 URL 反复解码或将 `+` 当作空格。不强行转小写或规范化磁盘文件名，大小写、Unicode 名称和文件身份按平台核验。

目标语法采用 [CommonMark 链接与图片](https://spec.commonmark.org/0.31.2/#links)，URL 编码遵循 [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986.html#section-2.1)。首版生成标准行内图片／链接，兼容解析引用式定义；不自动添加省略扩展名的查找、双链语法或私有协议。以 `/` 开头的现有路径不自动解释为工作区根目录，绝对路径、UNC 和 `file:` 目标须按独立的外部目标政策处理，不自动读取。

## 图片插入与存储

插入图片、拖入图片和粘贴剪贴板图像使用同一导入服务，默认目标为当前工作区 `assets/images/`。仅用户确实执行导入且需要写入时创建目录；目录已有内容就复用，不搬迁或整理已有资源。若该路径被普通文件占用、权限不足或无法核验实际目录，明确失败，不覆盖现有项或写到意外位置。

| 图片来源 | 处理 |
| --- | --- |
| 工作区外的图片文件 | 复制到受管目录，保留原件；成功后插入相对引用 |
| 工作区内已有图片 | 可直接引用现有位置，也可显式复制到受管目录；不因打开或粘贴一段 Markdown 自动重排图片 |
| 剪贴板位图 | 编码为明确格式的图片文件，默认 PNG；编码及写入成功后才插入引用 |
| 剪贴板中的 Markdown 或图片 URL | 按文本粘贴，不隐式下载、复制或迁移引用目标；外部网络图片默认不加载 |
| 未命名文档 | 先确定 Markdown 保存位置与所属工作区，再导入；取消保存选择则取消导入，不把图片放到随机临时基准 |
| 独立文件窗口 | 不隐式引入工作区；首版导入先确定文档位置并让用户选择图片目标目录，现有相对引用按文档目录解析 |

文件型图片默认保留原始字节，不为统一格式、压缩或去除元数据而静默重编码；剪贴板位图没有对应原始文件，按所选编码生成。格式、像素／字节上限及安全解码器由实施验证固定，未知或不支持格式显示原因。SVG 等带外部引用或活动内容的格式须通过受限静态处理路径准入，不作为任意网页文档交给预览执行。

名称优先保留可跨平台使用的原始主体，并用内容摘要后缀区分冲突；剪贴板图像使用稳定的内容派生名。现有同名不同内容绝不覆盖，摘要截断碰撞仍须比较完整摘要与实际内容或另取唯一名。只复用已核验相同内容的既有文件，不凭文件名或索引直接认定相同；复用对象也须满足当前授权。读取源文件后以本次取得的有限字节快照完成核验与写入，防止复制期间源变化产生误判。

导入顺序为：核对文档、只读／组合输入状态与授权 → 准备并安全提交图片 → 核验已写入对象 → 再核对文档与插入位置版本 → 通过会话编辑命令插入 Markdown 引用。不得先写入看似有效的引用、再把图片写入失败留给用户猜测。异步期间继续编辑使位置失效时重新定位或明确取消，不向旧偏移硬插；不将输入法临时组合纳入保存快照。

正文插入构成一次可撤销编辑；撤销仅撤销正文，不自动删除磁盘图片。图片可能被其他文档引用或已由其他程序使用，导入后取消、关闭或保存失败留下的文件应报告位置并列入待检查项，不自动删除已公布的资源。尚未提交的本次临时文件仅在身份及归属明确时清理。图片落盘和 Markdown 保存是两个结果，不能合称已经保存整篇文档。

## 图片与引用检查

图片管理至少能查询资源位置、哪些文档在何处引用它，以及引用目标缺失、不可读、被阻止或格式不支持的原因。目录内未被当前索引引用的文件只能称为“未引用候选”，不能称为可安全删除的垃圾；工作区外文档、尚未扫描内容和其他工具仍可能使用它。

不在移除引用、撤销、关闭、后台扫描或正常退出时自动清理图片。后续清理能力如要删除磁盘资源，必须另行定义用户逐项确认、范围及恢复措施；它不隐含在图片导入中。首版检查只提供定位与诊断，不承诺自动删除。

## 文档链接与打开行为

插入工作区文档链接时选择实际目标文件，正文写入相对当前文档的标准 Markdown 目标及可读文本，可附加标题片段。显示名称、目标路径和片段分别保留；重命名文件不擅自改写链接展示文字。文件扩展名保留，不猜测同名 `.md`／`.markdown`，不在缺失时自动创建空文档。

| 激活场景 | 结果 |
| --- | --- |
| 当前文档内的标题片段 | 在当前展示版本定位；不存在时提示，不改写源文 |
| 工作区内的 `.md`／`.markdown` 目标 | 经 `OpenIntent` 在当前工作区标签页打开；已存在会话则激活其所属窗口，保留未保存内容 |
| 独立窗口中的相对文档链接 | 经统一路由打开独立文件；已存在会话仍去重，不隐式打开父目录为工作区 |
| 工作区外、绝对路径或未授权文件目标 | 显示实际目标与原因，用户明确选择打开后仅授权该目标；不把一次点击扩大为目录扫描或工作区导入 |
| 目标不存在／不可读 | 显示断链或权限反馈，允许定位源文、修改链接或选择替代文件，不悄悄跳到相似文件 |
| 非 Markdown 本地文件或目录 | 首版不直接在预览中加载或执行；明确显示类型，用户选择后才交由系统允许的打开行为处理 |
| `http`／`https` 链接 | 用户主动激活后交系统浏览器；打开文档和后台检查不探测远端 |
| `javascript:`、`data:`、未批准自定义协议 | 拒绝执行并显示原因；不能因来自 Markdown 而绕过协议策略 |

编辑源文时普通点击用于光标操作，打开链接使用明确命令或平台约定的修饰键动作；阅读模式普通激活链接。两条路径使用同一目标校验，不让控件默认导航绕过应用路由。

标题定位由解析服务与预览共用一个有版本的标题到锚点映射；中文、格式标记、空标题、重复标题和 URL 编码在固定样例中确定稳定结果，插入链接时使用该映射生成片段。具体锚点生成算法在预览准入中固定并测试，不宣称已兼容所有网站的规则。定位目标为已打开的 dirty 会话时采用它的当前正文；文件可打开但片段不存在时保留目标文档并提示定位失败。修改标题引起锚点变化时提供诊断与修复预览，不静默批量改写其他文件。

## 引用索引

索引记录每条引用的来源文档身份、文本／磁盘基线、原文范围、原始目标、解析后路径与片段、目标身份、状态和索引代次。引用式链接须记录定义及其使用者：多个使用者共享定义时按定义更新一次；代码块、行内代码、转义文本和普通文字中的相似字符串不作为可改写引用。原文定位不足以安全修改目标时报告不可自动修复，不对整个文档做正则替换或重新格式化。

工作区内 `.md`／`.markdown` 为扫描范围，版本管理元数据目录不进入正文扫描；其他排除项、不可读文件、失败、取消和扫描上限都必须可见。不能仅因文件被 `.gitignore` 忽略就把潜在引用视为已检查。索引同时提供出站引用、入站引用、断链与未引用图片候选；这些是查询能力，不要求首版额外创建一个复杂的知识图谱界面。

已经打开的文档以会话当前已提交文本为准，包括未保存修改；未打开文档以核验过的磁盘快照为准。两者采用相同解析配置。预编辑未提交、过期分析、路径变化和关闭工作区都会使相应分析失效，不能让旧结果覆盖新引用状态。

索引从不成为写盘真相或访问授权。任何修改执行前重新核验文档版本、磁盘身份和写入权限；不完整扫描只能报告已知结果，不能声称“所有链接已修复”或“该图没有引用”。不为断链扫描访问网络、不扫描工作区外目录，也不把图片内容和完整私人路径写入遥测或公开日志。

## 移动与重命名

用户从应用执行文档、图片或目录移动／重命名时，先生成影响计划，显示将变更的路径、来源文档、引用位置、打开的 dirty 会话、将写入的未打开文件，以及未覆盖、只读或无法安全改写的项目。确认前不修改文件；用户若明确选择仅移动而不维护引用，必须看到相应断链影响。图片引用与文档引用遵循同一计划。

| 路径变化 | 需要重新计算的内容 |
| --- | --- |
| 文档改名或移动 | 其他文档指向它的入站链接，以及该文档自身指向图片／文档的出站相对路径；自身标题片段不因路径改变而随意改名 |
| 图片改名或移动 | 所有已识别到的图片引用，保留替代文本和标题 |
| 整个子目录移动 | 同时映射来源与目标的新位置，覆盖目录内互链、跨目录引用和资源目标，避免重复重写 |
| 工作区根整体搬迁 | 保持相对目录结构时正文通常无需改写；重新授权根目录并重建身份与索引，不写入旧机器绝对路径 |

确认后固定计划并重新核验基线。打开文档通过已有会话的范围编辑和撤销事务更新，保持原有未保存修改，不因批量操作擅自保存它们；未打开文档仅在用户已确认相应磁盘写入后使用统一文件保存服务。只读、组合输入、正在关闭、版本改变或目标冲突使计划失效，应跳过并明确报告或要求重新预览，不绕开会话直接写盘。

多文件修改不具备通用的原子事务。执行器逐项记录文件移动、正文修改和磁盘保存的真实结果，包括受影响会话尚未保存的引用。中途失败时保留所有已确认内容，报告部分完成、未执行和结果不确定项；不得伪报整体成功或假定整体回滚。恢复或反向计划也须核对执行后的最新基线，不能覆盖用户后来修改。文档内撤销保留；跨多个磁盘文件的一键全局撤销不作为首版隐含承诺。

跨工作区／跨卷操作需独立核验复制、身份变更、授权和删除阶段，不把它当作同卷重命名。未验证条件下不自动执行复制后删除原件的回退，提供保留原件的复制或另存为选择。应用外部发生移动／改名时，身份和监测仅用于提出可核实候选；不能凭文件名、时间或内容相似就静默修复所有引用。

## 授权与实际对象边界

显式打开工作区授予该根下正常文件的上下文，允许合法的 `../` 回到根内兄弟目录；独立窗口默认只提供文档目录上下文。在工作区未获授权或关闭后，不能仅因该文档曾在某工作区出现而继续读取其其他目录。普通文档链接的主动打开、图片持续读取与工作区索引扫描是不同授权，不互相扩大。

路径分量解析只是第一步，实际打开对象及中间目录的符号链接／重解析点也须在当前授权范围内核验，且抵抗打开期间目录项变化。仅词法去除 `..`、比较字符串前缀、查询规范路径或只拒绝最终文件链接均不足以放行。无法可靠核验时显示受阻原因，不静默读取范围外文件；平台方案由文件服务验证。

预览通过受控资源服务请求有限内容，不直接使用任意 `file:` 路径、裸目录浏览或内核默认网络加载。资源服务限制字节、解码尺寸与复杂度，实际额度通过样本确定；每个请求关联文档、工作区与路径／授权代次，迟到结果不能用于已移动文档或已关闭的工作区。实现入口可参考 [Qt 的自定义资源请求处理](https://doc.qt.io/qt-6.8/qwebengineurlschemehandler.html)，但注册协议本身不构成授权或沙盒。

## 实施顺序与验收入口

1. 在单文件闭环和文件／渲染基础之后，先实现普通图片导入、受控读取与标准相对链接，形成可用入口。
2. 建立同一解析配置的有版本引用索引，提供缺失、入站／出站引用及扫描覆盖反馈。
3. 基于索引加入预览确认的移动／重命名维护，覆盖 dirty 会话、未打开文件和部分失败；不以文件已改名代替引用维护完成。
