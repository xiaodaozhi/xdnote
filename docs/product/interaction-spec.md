# 交互规格

本文规定首版文档和窗口行为。界面布局参考[当前原稿](../../design/hifi/README.md)，精确尺寸见[视觉参数](../visual/tokens.json)。

## 统一打开入口

系统文件关联、命令行文件参数、系统文件打开事件、应用内选择、最近文件和拖入文件都转换为 `OpenIntent`，不各自实现一套会话逻辑。多个路径按输入顺序接收，最后一个成功打开的文档获得焦点；单项失败不阻止其他项，失败有对应文件的明确反馈。

| 输入 | 默认结果 |
| --- | --- |
| 双击 `.md`／`.markdown` | 独立文件窗口，初始阅读模式 |
| 工作区文件树、工作区内打开 | 当前工作区标签页 |
| 拖入某个工作区或独立窗口 | 先明确目标窗口意图，再进入相同去重与校验流程 |
| 同一文件已打开 | 激活已有会话及所属窗口，不再次读取以覆盖未保存内容 |
| 打开一个目录 | 仅作为用户主动选择的工作区，不由双击单个文件隐式触发 |

外部打开的目标和独立窗口初始模式可在[设置](settings.md)调整，只影响后续新会话，不迁移已经打开的窗口。

## 文档身份与窗口

应用以稳定的 `DocumentId` 识别文档，窗口只是会话的承载者。窗口重排、切换视图、修改配色不会新建编辑缓冲区或重置撤销栈。首版同一文件只有一个可编辑会话，不提供互相独立的多个编辑副本。

「在工作区打开」的行为：

1. 找到或建立工作区窗口，将当前文档会话移入其中的标签页。
2. 保留未保存文本、编码、换行、选区、撤销栈和文档身份，不以重新读取磁盘替代迁移。
3. 完成接管后再关闭原独立承载窗口；接管失败时原窗口继续保留。
4. 不移动源文件，不自动导入父目录，也不把打开一个文件扩大为任意目录访问。

## 视图与导航

- 工作区的编辑、双栏、阅读共享同一缓冲区；独立窗口仅展示阅读或编辑中的一个。
- 阅读模式中的任务框不响应修改，链接由用户主动点击。编辑模式通过源文改变任务状态。
- 分栏滚动同步以标题／段落映射为目标，不用两个面板滚动百分比相等冒充精确同步；实现尚待渲染验证。
- 侧栏可收起，窄窗口优先保留正文、模式切换和保存入口。菜单处理溢出，不缩小文字来塞入工具栏。
- 独立窗口标题栏显示文件名及未保存标记，父路径显示在下方工具栏的面包屑位置；图标按钮「在工作区打开」保留可读名称。长路径省略时提供完整可访问名称及查看位置入口。

## 文档状态

以下维度独立表达，避免把阅读模式当作已保存，把只读权限当作编辑偏好。

| 维度 | 取值与规则 |
| --- | --- |
| 加载 | opening、ready、error，失败时保留可关闭的明确错误页 |
| 修改 | clean、dirty，比较当前缓冲版本与最后确认保存版本 |
| 保存 | idle、saving、conflict、error，不覆盖加载／修改的真实状态 |
| 权限 | writable、read-only，实际不可写时给出原因与另存为入口 |
| 视图 | source、split、reading，独立窗口不使用 split |

状态栏仅在原文件提交成功后显示「已保存」。保存期间显示「保存中」，失败显示「保存失败」及重试入口，源文仍可复制或另存为。

## 保存与外部修改

1. 手动保存、自动保存与另存为使用同一个保存服务，按文档串行提交，冻结本次文本版本、目标和源文件基线。
2. 对已有文件，保留编码与换行；在同目录准备临时文件，完成写入与必要刷新后再提交，不先截断原文件。
3. 提交前检查源文件是否被外部修改、替换或删除。发现冲突时暂停自动写入，提供「保留当前编辑」「重新载入磁盘版本」「另存为」等明确选择；载入导致放弃编辑时再次确认。
4. 写入后若用户已继续输入，仅将本次快照记为已保存版本，当前文档仍为 dirty。过期保存回执不能清除新修改标记。
5. 提交前失败保留原文件和内存修改；提交之后发生刷新或回执异常时核对实际内容，展示结果不确定，不能声称原文件必然未变化。平台提交与竞争边界见[架构草案](../engineering/architecture.md)。

外部变化监测到 clean 文档变化时，提示可重新载入并保留阅读位置；dirty 文档不自动覆盖缓冲区。删除、权限变化、网络卷断开都进入可理解的失败或冲突状态，而非创建新文件假装保存成功。

新建文档首次保存由系统选择器确认位置和文件名。仅阅读文件、改变设置或打开工作区不会创建旁置恢复文件。崩溃恢复草稿属于后续独立设计，不作为当前关闭保护的前提。

## 关闭、批量关闭与退出

| 状态 | 关闭行为 |
| --- | --- |
| clean | 直接关闭对应视图并释放会话 |
| dirty | 提供「保存」「不保存」「取消」；关闭提示本身等同取消 |
| saving | 等待实际终态或取消关闭，不强行销毁缓冲区 |
| conflict／save error | 保留修改，提供解决冲突、另存为或明确放弃，不能默认为已保存 |

关闭其他标签只影响所属窗口，命令绑定稳定文档身份，不能随标签重排误关其他文档。退出先处理所有未保存文档，任何取消都终止退出；已完成的保存继续有效，尚未明确放弃的缓冲区不提前销毁。

托盘常驻与关闭到后台不列入首版要求。平台菜单和应用生命周期必须经过原生验证，不直接照搬 xdzip 的后台任务行为。

## 键盘与可访问性

控件的焦点外框遵守[控件交互与焦点显示](control-interactions.md)：常规指针交互不显示 outline，仅 Tab／Shift+Tab 导航需要时显示；激活、取消、指针交互或失焦后隐藏，逻辑焦点与文本光标独立保留。

常见保存、新建、打开、关闭、撤销／重做使用平台约定快捷键，Windows／Linux 的 Ctrl 与 macOS 的 Command 对应由平台适配处理。设置与模式切换均可键盘到达，所有图标动作具有可读名称，焦点离开菜单后回到调用控件。

主题、配色、分段控件保持单选语义；鼠标、键盘和辅助功能动作提交同一选择意图。不能只改变控件的勾选图形而不更新文档、主题或设置模型。
