# 控件文字垂直对齐核查

本轮对应 Issue #137，检查产品源码 `apps/desktop/src/` 的文字绘制入口和控件布局。产品基线为 `de7198d`，包含当前待合并的工作区欢迎页；不把这组结果归到较早的 `36a016c` 或尚未包含这些改动的 main。依据为[设计系统](../visual/design-system.md)、[共享参数](../visual/tokens.json)及[既有控件核对表](control-consistency.md)。本轮只增加诊断和记录，没有移动产品文字或更换字体。

## 结论

没有复现按钮、输入框、复选框、标签等控件统一向下偏移。Windows 原生字体后端中，常用中文的 14 像素按钮、输入框和复选框在 DPR 1 的可见字形中心偏差为 0；12、16 像素参考样本约为向下 0.5 个逻辑像素。DPR 2 的这些参考控件偏差不超过 0.75。设置卡片名称、文档页脚及缩放按钮也没有出现独立的整体下沉。

存在局部视觉差异和几何不一致，见 T01—T05。英文下伸字母造成的字形重心变化、离屏字体回退及整数取整必须单独判断，不能给所有控件统一添加负向 Y 偏移。

## 方法及证据身份

- 使用本项目 Qt 6.8.2、MSVC v143 构建。`xdnote_control_tests` 中的 `uiTextAlignmentSurvey` 使用 12／14／16 像素、中文、英文、数字、混排和下伸字母，比较普通／主要／禁用按钮、输入框、复选框、标签及 20 高页脚按钮，共 114 个参考样本。
- `uiTextAlignmentSurfaces` 实例化设置六页、独立窗口和工作区的阅读／编辑／双栏视图、文档查找、最近列表和菜单。明暗主题分别取样；设置、导航、窗口位置及文档均来自临时文件，不读取或覆盖用户配置。输入参考文字时阻断信号并恢复原值，避免搜索过滤改变采样对象。
- 原生取证仅运行上述两个隐藏夹具，使用 `WA_DontShowOnScreen`。没有使用 computer-use，没有操作用户窗口，也没有启动桌面产品供人工验收。离屏结果另存，不冒充真实桌面观察。
- 同时记录控件／文字区域、实际 DPR、字体及回退字体、行框、可见字形上下界和原始 PNG。偏差定义为“可见字形中心减去目标文字区域中心”，正值向下，单位为逻辑像素。紧凑标签使用区域内主要底色，像素筛选允许彩色抗锯齿边缘；单个阈值结果不直接判定缺陷。
- 原生标准采样的参考夹具 DPR 为 1，界面夹具主要为 1，菜单为 1.5；提高全局采样倍率后，参考夹具 DPR 为 2，界面夹具实际为 2／3。倍率以各条记录为准，不能把整组截图统称为 200%。
- 证据位于忽略目录 `build/cycle-137-text-alignment/`：`native-hidden/captures/`、`native-hidden/scale-2/captures/` 和离屏 `captures/`。每组含 `text-alignment-survey.json`、`text-alignment-surfaces.json`，后者保留界面、主题、对象名、窗口内位置及截图索引。原始图片是运行证据，不加入设计图目录。

QtTest 断言检查字形是否实际出现，并要求参考控件相对于同字号、同文本的原生 `QLabel` 基线偏差不超过 1。它能发现额外位移，不等于所有字符串的可见墨迹都应与控件盒严格对称，更不替代人工视觉验收。

## 局部差异及处理建议

| 编号／分类 | 具体对象、证据和影响 | 建议与优先级 |
| --- | --- | --- |
| T01 视觉偏差 | 设置六页的 24 像素半粗体标题。DPR 1 的“通用、外观与配色、编辑器、快捷键、关于”可见字形中心约 +1.5，“阅读与渲染”约 +1；文字行框仍居中。证据为 `surface-label` 的对应文字项与 `controls/*-text-settings-*.png`。 | 若要进一步追求光学居中，应仅针对这类页标题核对字形范围，同时检查标题与说明间距；不改变所有 UI 字体基线。P3。 |
| T02 基线计算不统一 | 工作区面包屑通过整数 `fontMetrics().ascent()` 手算基线，辅助标签使用 Qt 行框居中。本轮 12 像素样本中，前者可见中心约 -0.5、普通中文标签约 +0.5；两者不是同一字符串，不能据此认定需要固定补偿 1 像素。高倍率差异缩小但计算路径仍不一致。 | 后续用完全相同的路径文字对照，再统一同类辅助文字的行框／基线计算，保留各路径段共用基线和水平省略。P2；当前线索方向是略偏上，并非下沉。 |
| T03 已确认槽位几何不一致 | 菜单图标／勾选／箭头使用 `r.center().y()`，文字按整个行框居中。偶数 32 高 `QRect` 的整数中心比连续几何中心小 1，16 高图标槽因此比行框中心高 1。菜单截图保留了实际结果，但图形透明留白不等于可见字形。 | 统一槽位中心计算后再核对实际图形的光学中心，不能把这 1 像素全算成文字位移。P2。 |
| T04 已确认槽位几何不一致 | 文件树图标以 `cell.center().y()-8` 定位，文字使用完整行高。与菜单相同，偶数行的 16 高画布中心高 1；文字自身取样为 0。 | 统一树行图标槽与文字行框中心。可见图形包围盒仍需另测。P2。 |
| T05 已确认组合几何差异 | 最近／收藏／搜索结果委托先把行上下内缩 2；图标取整数中心。标题槽为内缩后顶部 +10、高 22；副标题为 +34、高 18。64 高行中，两个文字槽的整体边界中心为行中线 +1，图标画布中心为行中线 -1。标题自己的槽内取样为 0，不能误报为标题绘制偏移。 | 后续以整组文字和图标共同中心核对双行行项；保留已确认的整行宽度、左右内距及欢迎页边界。P2。 |
| T06 字体形状差异 | 独立窗口的混合路径、工作区英文目录名约 +1.5；相同控件的普通中文参考接近 0／+0.5。参考字符串 `gypq` 的可见字形中心天然更低。 | 保持稳定基线，避免输入或文件名变化时逐字符串上下跳动；该结果不作为控件布局 Bug。 |
| T07 离屏差异 | 本机离屏字体后端实际选择 Segoe UI／DengXian，而 Windows 原生后端选择 Microsoft YaHei UI。离屏中文参考约 +1.5，原生 14 像素参考为 0。 | 保留两组证据及字体身份；不依据离屏结果给原生界面添加统一补偿。 |

本表的槽位算术是源码已确认的几何差异，尚未实施整改；字形视觉偏差也不自动升级为布局缺陷。本轮不修改控件样式。macOS／Linux 的实际字体后端、真实桌面交互及系统原生控件仍未核验，不能从 Windows 隐藏夹具推定通过。没有运行完整桌面 CI。

## 复验入口

参考和界面夹具均在 `apps/desktop/tests/control_consistency_tests.cpp`，属于现有 `xdnote_control_tests`，日常可由[开发构建入口](../engineering/developer-build.md)中的 UI 测试范围执行。仅需这次诊断时选择 `uiTextAlignmentSurvey`、`uiTextAlignmentSurfaces` 两个 QtTest 函数，并通过项目运行环境设置 Qt 的 DLL／插件路径；原生 Windows 后端只运行这两个隐藏函数，不把其他会显示窗口的用例混入隐藏核查。

设置 `XDNOTE_TEST_EVIDENCE` 后输出上述 JSON 和原始 PNG；未指定时 JSON 写入自动销毁的临时目录。回归断言比较同字号同文字的 `QLabel` 参考，既能发现额外基线移动，也不会因不同平台字体的固有字形形状直接失败。
