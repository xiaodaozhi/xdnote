# 开发路线与阶段门槛

本页定义阶段产物和退出条件，不逐次记录任务执行报告。所有产品能力在实际实现和验收前保持待实现状态，当前仓库处于 D0 材料准备阶段。

| 阶段 | 产物 | 退出条件 |
| --- | --- | --- |
| D0 设计材料 | README、产品／交互／设置、视觉参数、完整图组与素材索引 | 链接、JSON、资产身份一致；需求与假设已区分，设计覆盖明确 |
| D1 技术验证 | 最小原生窗口、文档编辑与渲染试验、保存与系统打开试验、架构决策 | 用真实文件验证输入法、撤销、会话接管、原文件保存与冲突；据证据选框架、渲染与工具链 |
| D2 首版闭环 | 工作区、独立文件、设置、编码边界和保存保护 | FR-01 至 FR-08 与 NFR 的对应项目有实际证据，失败路径与跨启动设置通过 |
| D3 视觉与原生集成 | 组件状态、深色、其他强调色、多字号、关联与原生窗口材料 | 分别核对几何、行为、人工视觉与平台集成，不以截图存在代替运行检查 |
| D4 开发交付 | 可恢复源码、锁定依赖、统一构建入口、开发包和已知限制 | 同一来源能构建并在独立运行目录启动；已验证平台与限制明确 |
| D5 发行准备 | 许可证与来源、支持政策、安装与升级／卸载、签名策略、发行说明 | 对实际包逐项核验；作为单独的发行决策，不由 D4 自动触发 |

## D1 先回答的问题

1. Qt 候选能否在三平台满足中文组合输入、原生窗口、文件打开和资源部署要求；具体版本基于验证固定。
2. 谁拥有文本、选区和撤销栈；从独立窗口到工作区接管能否保持同一会话。
3. Markdown 渲染的方言、本地资源、脚本隔离、长文更新和定位是否满足首版。
4. 文件身份、同目录提交与外部写入竞争有哪些确定边界；保存失败、权限变化与卷断开能否保留修改。
5. 使用自有小／中／大样本测量后，确定启动、输入、渲染、内存和支持上限的预算。

这些问题应由小范围可运行验证收口，不先铺开全部窗口和发布系统。验证代码后续按实际职责放置，生成截图和报告进入忽略的 `build/`。

## 视觉补充顺序

当前静态图组已覆盖未保存确认、外部修改、保存失败、只读、空文档、菜单／焦点／禁用与浅深色等状态，见[界面清单](../visual/screen-inventory.md)。六种强调色共享几何与组件资产，已有六色明暗样本，不维护六套布局，也不把配色样本宣称为 12 套独立应用或运行结果。后续随需求变更补图；应用原生表现仍在研发阶段另行验证。

## 任务与决策管理

执行任务使用 GitHub Issues，记录目标、范围、验收、产物、依赖、实际证据与剩余项；分支、PR 与合并流程见[产研流程](../engineering/workflow.md)。docs 只维护当前规则、路线和可复用方法。

架构选择、平台支持和阶段边界变化需要留下理由与实际依据。若平台设备或签名条件暂缺，保留未验证项，不把其他平台的检查记成全面通过。新发现的缺陷独立跟踪，不不断追加到已完成阶段来改写历史结论。

## 首版之后

最近与收藏、搜索增强、HTML／PDF 导出、恢复草稿与会话恢复依需求逐项定义。云端能力、协作、插件和其他扩展不作为当前首版的隐性依赖。
