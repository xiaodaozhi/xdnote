# 视觉设计系统

## 方向与材料权威

界面采用接近白色的正文面、浅灰导航、深色文字、克制的强调色和细分隔线。空间优先留给文档，不加入仪表盘、营销卡片、账号入口或 AI 面板。

当前[高保真图组](../../design/hifi/README.md)包含 33 张图板、89 个页面与状态，沿用主工作区、独立阅读／编辑、外观与配色设置的简洁风格。精确颜色以 [tokens.json](tokens.json) 为准，窗口用途及建议尺寸见 [window-registry.json](window-registry.json)。位图由图像工具生成，存在绘制和文字细节误差，不作为逐像素的运行时事实。

用户已授权按当前图组开展开发。实施时共同遵循产品契约、共享参数与本规范；参考图中公共组件的偶然差异继续按统一规则处理。遇到规格冲突、平台限制或需要实质调整外观与交互时，记录问题、给出具体方案后与用户讨论，不将尚未执行的运行验收记为通过。

图组已覆盖浅深色主界面、独立窗口、设置、菜单、焦点、禁用、错误、关闭确认、冲突与扩展状态；六种强调色有[精确样张](../../design/assets/ui-v2/previews/accent-matrix.png)。完整索引见[界面清单](screen-inventory.md)。独立矢量素材与参考切片的使用方式见[交付说明](asset-handoff.md)，素材几何见[asset-geometry.json](asset-geometry.json)。这些是静态设计输入，原生表现仍待研发后验证。

## 颜色与组件语义

- 强调色名称与配置标识见[设置规格](../product/settings.md)。`base` 是选择器展示的基准色，`light`／`dark` 是对应界面使用的适配值。
- 主要动作使用强调实色和相应前景色；次要动作用中性描边或底色；选中文档使用低对比填充与细标记，避免整块深色干扰阅读。
- 已保存、警告与错误使用独立语义颜色并配合文字／图形。切换配色不能把错误变成普通选中态。
- 代码语法高亮与 UI 强调色分开管理。正文标题以清晰中性文字为主，不把所有标题、正文和数值染成品牌色。
- 共享按钮、开关、单选、下拉和分段控件统一处理尺寸、状态与键盘语义；窗口不分别覆写同类控件外观。

参数中的文字配色需在实际背景上检查对比度，主要文字以 4.5:1、非文字边界与焦点标记以 3:1 作为设计检查目标。不能以单纯看起来更浅代替实际检查。当前参数仍需实机验证，不表示无障碍认证。

## 品牌标记

用户已确认“折光”双色方向：两个填充色块以一条弧形留白分开，浅色与深色背景使用相应明暗版本。标记颜色和应用图标底色见 `tokens.json` 的 `brand`；可编辑几何见[品牌源](../../design/sources/brand-mark.cjs)。品牌标记与界面的六种强调色分别处理，石墨色仍是当前展示选择，不构成永久品牌色锁定。界面图的品牌标记经局部替换，应用图标的实际小尺寸显示与平台效果仍待原生验证。

## 逻辑尺寸与密度

所有参数使用逻辑像素。PNG 的宽高是材料元数据，不是窗口大小；DPR 只决定物理采样，不再次放大组件。操作系统窗口装饰按平台原生行为适配，不能把图中的 Windows 按钮直接复制为 macOS 标题栏。

初始参数按 8 单位节奏组织。UI 正文暂定 14，辅助文字 12，源文 14，阅读正文 16；这些是原生实现前的建议值。内容字号、应用辅助字号和系统缩放是独立维度，字号增大时布局可增长或滚动，不能用缩字抵消用户选择。

窗口参数由 tokens 管理，登记表引用同一键，不能维护另一组重复宽高。原生量测后若需修订，更新参数、依据及当前材料摘要；同一设计图使用稳定文件名保留最新版本。

## 跨界面公共组件一致性

同一公共组件只要出现在多个界面，就遵循同一套视觉和交互规则。主工作区、独立文件、设置、比较、导出及弹窗中实际出现的公共部分，都应按组件的用途与状态复用统一规范；某个界面没有该组件时，无需为了统一而增加它，也不要求各窗口具有相同内容或功能。

在同一平台、主题、强调色、字号与交互状态下，同类组件使用一致的逻辑尺寸、字体、行高、颜色语义、边线、圆角、间距、图标比例、命中区域及状态反馈。对齐和位置以组件所属容器为参照：保持一致的锚点、内边距、基线及相邻元素间距，不要求不同窗口中拥有相同的屏幕坐标。窗口伸缩和长文案可以按共享布局规则重排或截断，不能逐页面微调同一控件的基本样式。

标题栏中的品牌字标与文件名按统一的排版参照对齐，并检查实际可见字形的视觉位置；不同字体的度量差异由共享布局处理，不能只比较文本容器的几何中心，也不能将参考图的物理像素偏移直接作为运行时逻辑尺寸。

| 公共部分 | 统一要求 |
| --- | --- |
| 顶部栏与标题栏 | 相同类型的栏保持一致的高度、内容对齐和边距；品牌标记、标题及操作区采用统一尺寸和相对位置。文件路径等附加信息按窗口职责呈现。 |
| 窗口操作与关闭按钮 | 同一平台、同一类型的窗口操作按钮保持图形、尺寸、间距、命中区域及悬停／按下状态一致，并相对标题栏边缘一致锚定。标签关闭、弹窗关闭和窗口关闭按各自语义使用对应组件。 |
| 底部栏与页脚 | 相同用途的状态栏或页脚保持高度、内边距、文字基线、分隔线和操作区对齐规则一致；状态内容与按钮可因窗口职责不同而不同。 |
| 标签页 | 出现标签的界面复用标签高度、内边距、图标槽、文本与关闭按钮位置，以及活动、悬停、未保存、溢出等状态样式。没有标签的界面不增加标签栏。 |
| 图标、按钮及其他共享控件 | 相同语义使用相同图形、尺寸、描边、颜色语义和对齐方式；相同控件的默认、悬停、按下、禁用与键盘焦点状态使用共享规则。 |

主题和强调色变化时，通过共享参数映射到相应颜色与状态，不要求浅色和深色使用完全相同的颜色值。原生标题栏、窗口装饰和系统对话框遵循各平台的布局与交互习惯；若由应用绘制窗口装饰，同平台同类窗口使用统一实现。不同平台、不同职责的容器或有明确语义的组件变体可以有差异，但必须在规格和共享参数中说明依据，不能因参考图上的偶然差异单独实现。

参考图中同一公共组件的样式或位置不一致时，以本规范和 [tokens.json](tokens.json) 为准；缺失的参数须在实现前统一或明确所需变体，并同步相关窗口登记。主工作区与独立窗口的应用自绘标题栏统一建议为 48 逻辑像素，尚未经过原生量测。独立窗口在标题栏单行显示文件名和必要的未保存标记，父路径放在下方工具栏的面包屑位置；「在工作区打开」使用图标按钮并提供可读名称。独立窗口不因统一而增加标签栏。其他现有参考图保留为静态设计；系统原生装饰仍按平台约定处理。

## 三类窗口

| 窗口 | 结构与重点 |
| --- | --- |
| 主工作区 | 标签、导航、工具栏、源文／预览与状态栏；分栏边界对齐，侧栏可收起 |
| 独立文件 | 文件名和父路径、模式切换、局部动作、单一正文与保存状态；不强制出现资料库 |
| 设置 | 左侧分类，右侧分组；主题与配色分开；选择色块配合当前控件预览 |

窄主窗口收起可选导航或调整展示模式，保留可到达的保存和视图入口。设置窗口变窄时配色色块从一行重排为多行，正文滚动而「完成」保持可达。独立窗口和工作区中的相同控件保持同一字号与命中区域。

## 状态覆盖

焦点样式仅用于 Tab／Shift+Tab 导航中必要的当前位置提示。普通点击、悬停、按下、自动聚焦不显示额外 outline；激活、取消、指针交互或失焦后清除外框。控件逻辑焦点、文本光标、选择与错误边线分别处理，完整时序见[控件交互规则](../product/control-interactions.md)。组件图册中的「焦点」列按此键盘状态理解。

| 组件 | 必须覆盖 |
| --- | --- |
| 按钮 | 默认、悬停、按下、焦点、禁用、执行中 |
| 单选／开关／分段 | 当前选择、非选择、键盘操作、辅助功能、禁用 |
| 文件与标签 | 活动、非活动、未保存、关闭、长名称、溢出 |
| 下拉／菜单 | 展开、键盘导航、禁用、边缘翻转、关闭后焦点归还 |
| 正文 | 空文档、只读、加载失败、长行、代码、中文组合输入、滚动 |
| 文件反馈 | 保存中、保存失败、外部冲突、未保存关闭 |

状态不能仅靠颜色区分。图标动作有可读名称，Tab 顺序与视觉顺序一致，分段、主题和配色维持单选而非若干可独立取消的按钮。

## 设计到实现的交付

1. 阅读需求、交互与窗口清单，确定这次修改的范围和待补状态。
2. 在唯一参数文件定义新值及适用条件，再准备可编辑组件和窗口；不从实现结果反向改写原稿来证明一致。
3. 同时对照主窗口、独立窗口、设置和菜单的字号、行高、图标槽、边距与焦点，不只单独检查一个对话框。
4. 记录逻辑窗口、系统缩放、DPR、字体、渲染后端和实际提交，进行原生几何、行为与人工视觉检查。
5. 设计输入和来源进入 `design`，实际截图及测量进入忽略的 `build/`。检查与限制依照[验收规格](../qa/acceptance.md)记录。

不在初始静态图上填写虚构的“还原率”。对照图和代码读取同一组参数，只能证明参数一致，不能替代独立原稿与真实交互的检查。
