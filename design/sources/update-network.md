# 更新网络设置交互提案

本提案复用设置窗口与共享控件，需确认组内保存语义及人工视觉；不代表已合并或已完成原生验收。现有六页结构、窗口尺寸、主题和强调色保持既定规格。

入口位于「关于」的更新操作之后，分组名为「更新网络」。普通宽度使用现有左右表单；紧凑宽度依照共享阈值上下重排，侧栏、正文滚动及固定底部「完成」沿用现有实现。

| 字段／操作 | 行为 |
| --- | --- |
| 更新代理 | 系统代理、不使用代理、自定义代理；只修改本组草稿 |
| 代理地址 | 自定义模式启用；无凭据 HTTP CONNECT／SOCKS5 地址及显式端口 |
| 更新镜像 | 可选 HTTPS 前缀；留空使用官方地址 |
| 保存网络设置 | 三个字段一起校验并原子保存；失败保留草稿与已生效配置，沿用统一错误和重试 |
| 恢复已保存 | 丢弃本组草稿，恢复已保存字段；不改变系统代理 |
| 完成／关闭 | 关闭窗口；不额外提交本组未保存草稿 |

组内草稿与已保存偏好明确区分：编辑时显示「网络设置尚未保存」，检查和下载继续使用已保存配置。保存后只用于下一次主动检查；当前检查、下载和原生安装保留原快照。其他偏好仍按现行规则即时生效。

采用单独保存是为了避免用户选择自定义模式、尚未输入完整地址时保存半份网络配置。无效已存配置仍暂停更新，不能把展示用默认值视为已确认的网络选择。该组内保存例外需与产品设置规格同步确认。

输入框沿用共享 32 高、字体、边线、内容内距及 Tab 焦点规则；长地址字段采用 `settings.longFieldWidth`，可用区不足时收敛，不缩小字号。Store 副本不展示 GitHub 更新网络表单。

离屏预览、控件回归和紧凑可达性只属于工程证据，不替代可见桌面、真实代理／PAC、最低系统和生产更新验收。单次预览与结果记录在 Issue #166／PR，运行图片不纳入源码。
